# K4: platform migration to kernel v0.2

Compile each engine's ingress declaration into `IngressStream(id, policy,
mapping_id, engine_ids)` and pass the tuple as `Kernel(ingress_streams=...)`.
Distinct streams may have different policies and mappings; remove the platform's
run-wide policy equality requirement. A stream can bind several engines; an
engine can bind several streams. Each real-time engine requires a binding.
Commands name a stream and target only its declared engine domain.

Keep `Kernel(ingress_policy=...)` for intentionally shared single-stream scenarios;
its calls use `stream_id="default"`. Engine-named streams have no implicit alias.
Compile an explicit `default` stream or send its actual ID.

In `wt-q1/src/aeroagentsim/platform/ingress.py`, decode a `stream_id` and call
`kernel.admit_live(command, stamp, stream_id=...)`. Return the kernel's typed
`IngressReceipt` after WAL acknowledgment, including `code="LATE_INGRESS"` for
rejections. The `IngressJournal` interception layer can be removed. Existing
`submit_live` returns a command ID and raises `LATE_INGRESS` on rejection.
`ingress_receipt(command_id)` retrieves the original accepted/delayed receipt
without a journal scan. Idempotency is scoped by stream and preserves original
receipt/index for rejections too. Use a versioned platform receipt schema that
includes `stream_id`. Admission does not establish engine acceptance or success.

Decode optional `allowed_lateness_ns` as a nonnegative integer (bool is invalid).
For **explicitly asserted source progress** `P`, call
`advance_source_progress(stamp, stream_id=...)`: the kernel maps `P` and closes
`P - allowed_lateness_ns`. Absent allowance subtracts zero. The open tail admits
inputs strictly greater than that closed prefix, including `P` when the bound
is positive. Progress below the initial/current closure is invalid; do not clamp
or infer it from an input timestamp. `advance_watermark(ns, stream_id=...)`
already asserts a **closed canonical prefix**, subtracting nothing. Adapters may
instead perform the subtraction themselves and use this API; subtract once.
`timeout_s` remains the wall-clock wait budget, independent of ns lateness.

An independent fast engine can advance/react at the selected boundary while a
slow engine waits. `run_until` returns after the common global seal; committed
views/receipts expose partial live progress. A seal requires all relevant streams
and due work. Inputs arriving after a partial commit retain source time and get
a publication boundary after the current journal instant, preserving causality.

Update `tests/platform/test_realtime.py` to accept different policies on different
streams, reject inconsistent declarations of one stream, check mapped progress
and allowed-lateness edges, and verify typed rejected/idempotent receipts. Keep
old single-stream tests. Journal 1.3 pins complete live declarations; 1.2/1.1
journals replay unchanged. Offline workloads retain 1.2 output bytes. The SDK
`LiveIngress(kernel, stream_id)` provides a stream-bound adapter handle.

No platform files were modified; distributed synchronization remains out of scope.
