# K5 migration and measured limits

K5 preserves execution/provenance semantics and the default 1.x encoding. Select
`Journal(path, codec="positional-deflate")` explicitly to write journal 2.0.
The header admits `positional-deflate/v1` and the underlying 1.2/1.3 semantic
version. `replay(Path(...))` now streams both generations. Use
`aerokernel.journal.iter_records(path)` for incremental codec expansion and
`aerokernel.compact.expand_record(record)` for semantic fact rows; use replay when
transaction validation is required. `kernel.iter_records()` returns detached
semantic records without materializing the whole history tuple. Keep file-backed
journals available for the lifetime of their issued views.

## Platform changes

1. Select the new codec at Simulation/RunSession journal construction, and pin
   it in exported run metadata. Replace projections that directly assume inline
   `items` in every JSON line with the streaming expansion API. Raw histograms
   may still use the outer `type`, `phase` and `index`. Retain 1.x import support.
2. In `src/aeroagentsim/engines/predicate.py`, retain the same ordered `prior`
   frames/history passed to the native evaluator. Replace the loop appending each
   `recorded.version` to `ctx.inputs` with the single
   `ctx.view.sample_frame_prefix(self.spec.context_id)` at the identical position.
   `FramePrefix` is admitted only under 2.0. Prefix expansion preserves the entire
   ordered sequence and duplicates; it is not merely the final frame's cause.
3. Verify the expanded causes against the existing Q6 output before adopting.
   The SDK currently removes duplicate cause tokens: a prefix overlapping an
   earlier explicit cause is not the same token as that cause. Producers must
   preserve their current first-occurrence sequence when forming prefix/tail
   segments, rather than accidentally reintroducing duplicates at the boundary.
   Low-level operation causes deliberately preserve repeated prefixes.
4. Behaviour record subscriptions currently adopt committed frame/event refs.
   Keep that evidence route. Replacing it requires an explicit kernel-supported
   committed evaluation reference, with the same read-cut, ownership and delivery
   checks; silently omitting the subscription is not a performance fix.

## Measurements

The unchanged platform `profile_runtime.py` ran from the platform working
directory with the full 63-vehicle/8-UAV scenario at nominal 15 Hz. All output was
written in the kernel workspace. The new-codec runs use the workspace wrapper
`.kernel-agents/k5/profile_compact.py`, which changes only Journal construction.
The platform source was not edited. All values below are actual measurements,
not 90-second extrapolations.

| --- | ---: | ---: | ---: | ---: | ---: |
| Platform §13 baseline, legacy | 3 | 289.952 | 0.01035 | 50.294 | 197.7 |
| K5 authority index, legacy | 3 | 31.888 | 0.09408 | 50.294 | 237.0 |
| K5 positional/DEFLATE | 3 | 33.442 | 0.08971 | 4.356 | 146.3 |

The 30-second run completed and sealed at 30,000,000,000 ns (8,422 records after
its header). It predates the final sharing of immutable fact authority entries;
that later fix is covered by the final gates/benchmarks, not represented as a
remeasured demo result. A 90-second run was not attempted: the measured 30-second
journal and RSS already exceed the entire 90-second allowances. The live targets
are **not achieved**. Callbacks alone took 141.382 s at 30 seconds, including
91.822 s in behaviour reactions and 37.831 s in sampled evaluators, so removing
all remaining coordinator cost could not yield RTF 2 for this unchanged platform.

Engine-free replay of the 30-second journal was still running after at least
1,155 wall seconds and was interrupted. No completed replay cut or peak RSS was
captured; replay is not claimed to meet its target. The prefix metrics above are
not substituted for a completed replay measurement.

## Required next representation change

Compression preserves all values, but it does not remove construction,
normalization or repeated traversal of expanded historical causes. The new raw
FramePrefix still expands into resolved ItemRef tuples. Long Q6 contexts also
retain and re-thaw prior evaluation inputs; dispatched messages and intent inboxes
retain full encoded trees. These costs remain superlinear.

To meet the targets while retaining exact evidence, a further normative amendment
must add an immutable **ordered segmented cause sequence** to resolved frames,
messages, events and deliveries, not just proposals. Each segment is either an
explicit ItemRef sequence or `(context_id, prefix_count, boundary_item)`, with
in-place expansion and duplicates preserved. Define first-occurrence SDK handling
explicitly. Validate context/boundary/read-cut authority once; keep small indexed
membership/lag metadata; expand only on an explicit diagnostic/provenance query.
Journal the segment nodes once and reference their committed coordinates from
later effects. Backreferences must be strictly earlier, schema-pinned, bounded,
and corruption-checked; every old flat sequence must expand identically.

Similarly, dispatch/intent records should reference actual earlier Message/Dirty
items and sampled frames should reference the header SampleSpec plus explicitly
versioned input deltas. Missing/null/unknown, clock/source identity, and changed
values must remain distinct. File-backed immutable payload nodes are needed so
Store.intents/frames/messages do not retain repeated full trees in memory.
These changes must reach SDK/RPC projections and engine-free replay together;
encoding alone cannot satisfy the RSS/time limits.

Q6/behaviour then need an audited incremental or window-indexed native evaluation
path and indexed behaviour dispatch, preserving the same truth, unresolved/gap
semantics, diagnostics, frame publication and evidence. The 30-second callback
floor establishes this need independently of any proposed kernel codec speedup.
No sampling rate, actors, causes or recorded notifications were dropped in K5.
