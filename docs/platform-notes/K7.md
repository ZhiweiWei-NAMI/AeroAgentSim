# K7: default lean provenance

Release implementation uses the K5 tree (0e10c1f), without K6's four new
representation/storage modules. `Kernel()` defaults to `provenance="lean"`;
`provenance="full"` preserves K5 audit semantics and existing journal bytes.

Lean drops explicit read vectors, their scope/expansion checks and SDK vector
construction. Each resolved engine operation/message/frame cites its invocation;
the WAL retains its inputs and read cut. The live index retains pending inputs
and compact operation mappings for the latest returned call per partition/phase.
Time seals, conservative grants, field ownership, typed payloads,
actual dispatch/target authorization, receipt transitions, cancellation correlation,
cleanup acknowledgments, ingress watermarks and deterministic replay remain.
Admitted payloads/generated journal metadata are serialized without another audit
copy. Input budgets and final frame limits remain checked. DESIGN §16 is normative.

Lean journals are JSON 1.4 or compressed 2.1 (`canonical-deflate/v1`); full
1.x/2.0 replay remains supported. Experimental K6 journal 3.0 is not a release
format. Full-mode toy output was compared byte-for-byte with the installed K5.

The real 71-actor demo used read-only wt-a at 26304c3, including real browser
capture, 30 simulated seconds per rate. Wall includes scenario loading/bootstrap.
Journal MB are decimal; RSS is MiB. No Docker or engine substitution was used.
On the 3-second prefix, 506 records and 13,604 committed state/message/frame/
receipt effects match the previous encoding, excluding only audit causes.

**15 Hz is not accepted:** throughput, journal and replay targets are missed.
The best measured rate reaching RTF ≥1 is 1 Hz. Callback time at 15 Hz totals
26.33 s (road motion 11.23, behaviour 7.28, two main sampled evaluators 6.20);
the remaining wall time includes 9.61 s bootstrap and kernel work. A separate
3-second cProfile shows cumulative `build_wave` 8.80 s, operation validation
8.16 s, value normalization 6.82 s, encoding 4.40 s, invocation construction
3.55 s and Journal.append 2.77 s; these overlap and are not additive wall costs.
There is no proof that the target is impossible in Python. Next work should
reduce repeated typed payload/metadata traversal and apply admitted resolved
effects directly during lean replay, rather than rebuild proposal transactions.
Within-record delivered-input references could reduce duplicated inbox data;
segmented provenance is unnecessary for this direction.

## Integration on main b4b61ed and platform ed29e4b

The scheduling/RPC conflicts are resolved on `perf/k7-main`. Full retains main's
complete returned intents and unchanged journal bytes. Lean retains at most four
compact returned mappings per partition (bootstrap/advance/react/sample), plus
pending intents. This supports behaviour's A5b emission resolution on its next
input callback even when advance calls intervene. Engines resolve before that
phase returns again and retain the resulting ItemRef; superseded mappings are
`CAUSE_UNKNOWN`. Issued views retain their own immutable mappings. SDK, RPC and
engine-free replay use the same retention rule.

Platform `perf/k7-platform` exposes scenario `provenance: lean|full`, constructor
overrides and `run`/`demo --provenance full`. The effective level is pinned in the
run manifest and any overridden scenario copy; the caller's scenario is unchanged.
Audit-detail tests explicitly request full, while realtime tests assert lean's
new header and retain their receipt/time/replay assertions.

The public demo explicitly uses lean and **1 Hz** physics/publication. This is the
measured rate reaching real time; 2 Hz has not been measured. Playback's position/
quaternion interpolation smooths bracketed recorded samples without changing
committed facts or exact cuts. Current live-follow follows newly committed cuts,
so it still steps; it does not extrapolate unknown future states. A buffered
display timeline would be separate frontend work.

The successful `aeroagentsim demo traffic-accident --headless` run reached stored
capture at 26.94 wall seconds and verified/accepted upload at **27.06 s**
(49.266666667 simulated seconds). The full 90-second run, including final indexing
and outcome reporting, took **66.48 s** (RTF **1.354**), journal **10.62 MB**,
RSS **168.84 MiB**. Timing observed completed publication without modifying WAL
records. The first observer launch failed at bootstrap on a routing ID; its filter
was corrected before the successful full run. The earlier 30-second table is a
separate wt-a measurement, not replaced by this public-clone run.
