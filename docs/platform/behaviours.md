# Behaviour packages and the chain runtime

Implemented as of 2026-10-08 in this worktree; this document describes the code that exists, not a target. It covers the actual behaviour package format, compiled IR, automatic bindings, the two evaluation profiles, the injection gateway, records/causes, deterministic ordering and replay, and the legacy compatibility executors. [RUNTIME.md](RUNTIME.md) remains the normative design; where the implementation deliberately differs (sampled wiring, feedback lag, selectors, completion schema), the differences are listed in [§11](#11-exact-deltas-against-the-runtime-target) without re-stating the design as fact. All paths are relative to `src/aeroagentsim/`.

## 1. Modules and engine selection

| Module | Contents |
| --- | --- |
| `behaviours/schema.py` | `FORMAT = aeroagentsim.behaviour-package/v1`, `IR_FORMAT = aeroagentsim.behaviour-ir/v1`, `CompileError(source, path, message)`, frozen `PackageIR` with `to_data()` embedding `digest`, `ir_digest` and evaluator source hashes. |
| `behaviours/compiler.py` | Authored-path validation (`Compiler`), `compile_package`, `resolve_packages` with content-pinned imports, `UniqueLoader` (strict bools, duplicate/nonstring YAML keys rejected with line numbers). |
| `behaviours/bindings.py` | `stable_id` (sha-256 over `canonical_json`, namespaced by prefix), `live_refs`, `tuples` role-tuple selection over real `is_a` ancestry. |
| `behaviours/evaluation.py` | `Truth` and `Evaluator` — committed-reactive evaluation of the Q6 AST as a library, with bitemporal truth records and discontinuous baselines. |
| `behaviours/records.py` | `aas:BehaviourInstance` overlay type, `aas.behaviour.*` fields/events, `aas.runtime.inject_event`, `overlay()` descriptors, lossless `instant(ns, microstep)`. |
| `behaviours/compat.py` | `LegacyWorkflowExecutor` and `LegacyThresholdExecutor` plus their descriptive IR functions (§10). |
| `engines/behaviour.py` | `Behaviour` executor (`build`), `build_legacy_workflow` / `build_legacy_threshold` selectors, `RecordedPredicate` sampled adapter. |

The catalog maps the single plugin name `behaviour` to `aeroagentsim.engines.behaviour` (`platform/plugins.py` BUILTINS). One factory module selects all three executors: `build` constructs the compiled chain runtime; `build_legacy_workflow` / `build_legacy_threshold` construct the pinned legacy interpreters from `behaviours.compat`. The retired `engines/workflow.py` and `engines/threshold.py` modules are thin lazy aliases that re-export those two selectors; the compat module is imported only when a legacy factory is actually called.

Scenario wiring (`scenario/loader.py`): a scenario enabling behaviours declares exactly one `plugin: behaviour` engine and an additive top-level `behaviours` list. The loader resolves packages once from the scenario root, installs `overlay()` into the registry (conflicting authored IDs are a `ScenarioError`), and appends the writer rule and lifecycle controller for `aas:BehaviourInstance` scoped to `behaviour:*`. When a behaviour engine is present, `platform/simulation.py` constructs every `predicate` engine as `RecordedPredicate` instead of the plain Q6 engine (§8).

## 2. Package format, compilation and digests

`compile_package` validates at the authored path and fails closed before any world binding: format/id/revision, `evaluator.version` equal to the Q6 `aerograph-predicate/1` VERSION, budgets (`max_transitions_per_instance_per_ns`, `max_instances` required; `max_timers_per_instance`, `max_creations_per_instance` optional), predicates, chains, bindings, conflicts, injection points and `bootstrap_relations.assertions`. Structural highlights:

- **Expressions.** `$role`, `$variable`, `$trigger` and `field`+`role`(+`path`) reads are validated as typed expressions, not string substitution. `$variable` must be declared on the binding, and its schema (resolved through the source field and path) must match the destination member type. `$trigger.payload.…` / `$trigger.result.…` paths are checked against the actual trigger message/result schema. Payloads without expressions are validated directly against the destination schema.
- **Selectors are not computations.** Expression objects containing `stable_id`, `stable_entity_ref`, `relation_assertion_id`, `typed_choice`, `choose`, `selector` or `minimum_known_feasible_eta` fail with "unsupported computation; use a typed command/event from an explicit domain computation owner". The internal `stable_id()` helper in `behaviours/bindings.py` is a digest function over instance inputs; it is not an authored selector.
- **Ownership.** `set` and `create_entity.facts` require the field to be applicable to the target type and actually owned by this behaviour partition per `EngineBuild.owned_fields`. `create_entity`/`remove_entity` require this partition to be the unambiguous lifecycle controller; `assert_relation` requires it to be the relation writer at top priority.
- **Capabilities.** A `command` action declares either a `capability` resolved from engine config to exactly `{schema, target}`, or explicit `schema`+`target`. Emit/command payloads must cover the registered message schema.
- **Trigger categories.** Exactly one of `predicate` (with `edge: entered|exited|while`), `event`, `timer`, `receipt` (explicit `status` list, `policy` all/any), `lifecycle` (`created`/`removed`), `instance` (`activated`/`continued`), `deadline`. State timer/receipt/deadline references name authored action IDs (or `instance` for deadlines). A template timer trigger is `{timer: release, after_ns: 3}`; zero means the next microstep. Initial receipt/deadline triggers are rejected because no child yet exists.
- **Transition policy.** Only `first_enabled` compiles. Transition and binding IDs must be unique; action IDs are unique within a transition, while a terminal child may be reused by a later state. Chain-level `variables` are rejected: variables are declared per binding where their sources resolve.
- **Completion policy.** Shape is exactly `{children, statuses, policy}` with `policy` in `{all, any}`, nonempty `children` ⊆ authored action IDs, and statuses drawn from the receipt vocabulary. Enforcement is at terminal entry in the executor (§5).
- **Sampled predicates.** A predicate with `profile: aerograph_sampled/v1` must carry `adapter` with exactly the keys `{event, context}` (§8); nothing else compiles.

`resolve_packages` accepts inline documents or `{path, sha256}` files loaded with `UniqueLoader`; external references are hash-pinned, cycles are rejected, and the same package ID with a different digest fails the closure. A spec already in `aeroagentsim.behaviour-ir/v1` form (previously resolved) skips re-traversing its imports and recompiles its embedded document.

`PackageIR.to_data()` carries two digests: `digest` (sha-256 of the canonical document) and `ir_digest` (sha-256 of the semantic IR: format, document, per-predicate `(role, field)` dependencies, and the evaluator block `{version, sources}` with sha-256 hashes of `engines/predicate.py` and `engines/predicate_ast.py`). Loading resolves and pins the closure; construction links the actual registry/manifest authority. Neither stage occurs per tick. Runtime still validates actual messages and commits.

## 3. Automatic bindings and instance lifecycle

`tuples(ctx, registry, roles, match)` selects role tuples from live entities at the invocation's committed cut: per role, candidates are filtered by real `is_a` ancestry (chain role type plus optional selector `is_a`), exact `entity` ID, and `field` selectors (`equals`/`in`; `Absent` excludes). Relation selectors join real source/target endpoints before taking the Cartesian product of remaining roles. Live refs are sorted by `(id, generation, type_id)`; matched `(edge_id, record_index, item_index)` versions become part of the episode key.

`_bind` runs on its first committed invocation, relevant entity lifecycle or relation changes, and changes to declared selector/episode fields. Its own journal notifications do not cause rebinding. For packages in config order and bindings sorted by ID, the instance identity is

```
stable_id([run_id, epoch, package_digest, binding_id, chain, sorted role refs, episode])
```

with `episode` being the relation edge-version tuple for `once_per_relation`, the thawed `episode_field` value for `once_per_task_episode` (default role `task`; absent field skips), and `None` for `once_per_entity`. Reasserting the same edge version does not re-instantiate; a new episode or generation does. `max_instances` is enforced per package and faults with the binding and cut. The instance ref is created (`aas:BehaviourInstance`, generation 0) before variable resolution. When a declared variable source has not committed yet, the instance records `status: waiting_inputs` and `requiredInputs` with its entity, field and configured producer. Its declared field dependency wakes it when the actual fact arrives; no value is synthesized. Once inputs commit, variables resolve and activation proceeds.

Lifecycle statuses: `dormant` → `active` → `completed` / `failed` / `canceled`, plus `waiting_inputs` and the transient `cleanup`. A `close_after_cleanup` binding that stops matching marks the instance `cleanup` while children are non-terminal, requests cancellation only from command owners that advertise it, and records `canceled` once real terminal receipts settle; `retain_until_terminal` keeps history without erasure. The `created` record is emitted the first time the created ref is visible in the invocation cut — the lifecycle controller creates the instance before its overlay fields publish.

## 4. Predicate evaluation profiles

Reactive truths use `aas.behaviour.records`; native sampled frames use `aas.behaviour.sampled`. Both produce `Truth` records with `contextId`, `predicateId`, bound roles, `status` (`known` / `required_input` / `invalid_input`), `value`, `diagnostics`, `evaluatedAt`, `readCut`, `acquired` clocks, and `validFrom`/`validTo` assert/close pairs. Unknown and invalid always carry diagnostics and a null value — never a fabricated Boolean. Diagnostics name the role, entity, field and configured producer (`store.writers`).

**`committed_reactive/v1`.** `Evaluator.run` reads each `field` node's committed fact at `ctx.now`, collects fact versions and `acquired` stamps (clock, mapping, numerator, denominator and actual producer), and reads declared relations as presence. Reverse indexes dispatch changes by `(EntityRef, field)`, entity generation and relation ID. Registered contexts continue to update on relevant commits after a chain terminates, so their recorded intervals do not remain open with stale truth. A `(versions, roles, diagnostics)` signature that is unchanged returns the previous truth without re-emitting. Otherwise the Q6 AST evaluator (`predicate_ast.evaluate`) runs as a library over a single frame `{t, fields, relations, parameters}`; the result must be Boolean or None, and None becomes `required_input`. `TypeError`/`ValueError`/`ArithmeticError` become `invalid_input`. Temporal/window operators (`TEMPORAL`: `hold`, `delta`, `all_window`, `any_window`, `count_window`, `rate`, `rise`, `fall`, `changed`, `stable_window`, `entered`, `exited`) and `time` leaves are rejected at compile time in this profile — there is **no native temporal evaluation in the reactive path**; the Q6 evaluator is used statelessly over one settled frame. Each package selects the supported `original` or `expanded` Q6 dialect; the choice is part of its pinned document and digest.

Edge semantics are wrapper-local, not native AeroGraph `entered`: `while` is known-true now; `entered`/`exited` compare with `previous`. The baseline is deliberately discontinuous: `previous` is `None` (no edge) when there is no prior truth, when the prior status was not `known`, or when any role's source producer or `acquired` clock/mapping pair changed — a source or clock swap breaks continuity instead of producing a spurious edge. Initial true and unknown→true therefore produce no `entered`.

**`aerograph_sampled/v1`.** Never recalculated reactively. The predicate declares `adapter {event, context}` naming an explicit Q6 `predicate` engine and its pinned sampled context (§8); the executor consumes that engine's recorded truth deliveries keyed by `contextId`, requires the recorded roles to equal the instance's bound roles, and uses the delivery ID as the freshness signature. If the sampled expression's top-level `op` is `entered`, `exited` or `transition_event`, the edge was already produced by Q6 and the wrapper does not apply a second edge detector — the trigger matches on known-true. Otherwise the wrapper's `entered`/`exited`/`while` semantics apply across successive sampled frames, with the same unknown/clock-change baseline breaks.

Trigger firing requires the context to be fresh in the current invocation: a `while` trigger fires at most once per eligible evaluation revision (including the explicit first evaluation) and does not reactivate itself because it wrote a field; a repeating chain needs a positive delay, a new event, or a new dependency change.

## 5. Execution wave

`on_inputs` is one invocation at one immutable cut:

1. **Bootstrap and deferred work.** `bootstrap_relations.assertions` are related once with canonical stamps. `create_entity` facts collected in a previous wave are written now — new identities publish their initial facts in a later writer wave.
2. **Inbox.** Command deliveries go to the injection gateway (§7). Event deliveries become trigger inputs, except the executor's own recorded messages: sampled `predicate_evaluated` asserts update the sampled cache; reactive `predicate_evaluated` asserts re-attach the journaled delivery's origin as the matching truth's cause (a `LocalCause` from the emitting invocation cannot be cited later and is cleared); other `aas.behaviour.*` events are journal notifications unless explicitly named by an authored event trigger.
3. **Receipts and timers.** `submitted` receipts correlate the next pending child to its command ID; subsequent statuses update the child and are recorded as a revision when the instance is published, with the receipt's journal `{record_index, item_index}` retained. Terminal receipts cancel the child deadline timer. Fired timers are matched by instance, action and state-entry revision; stale revisions are dropped.
4. **Binding**, then **conflict rules** (§6), then **candidates**.
5. **Publish.** The overlay fields (`aas.behaviour.template_id`, `binding_id`, `roles`, `state`, `revision`, `status`, `children`) are written for every touched instance at the end of the wave.

Trigger matching (`_trigger`) supports the compiled categories: `instance: activated` once on dormancy exit, `continued` set after each non-terminal transition; `lifecycle` against dirty lifecycle records for bound roles (with an alive check), or the implicit `created` for dormant instances; `event` with typed-equal correlation; `predicate` per §4; `timer`/`deadline` payloads; `receipt` with all/any policy over explicit child action IDs and a matching delivery in this wave. Optional `result_matches` compares named members of the actual typed result; `any` selects a child whose real status/result matches.

**Ordering.** Instances are scanned in `(bindingId, instanceId)` order; enabled transitions are collected as `(-priority, bindingId, instanceId, authored index)` and executed in that sorted order, one transition per instance per invocation (`first_enabled`; another policy does not compile). Guards all read the same invocation cut; a dependent continuation runs in a later microstep via `Activate`. Conflicting `set` slots and relation edge/cardinality reservations are arbitrated in execution order: the first candidate reserves each `(EntityRef, field)` slot and a later colliding candidate is skipped with an `aas.behaviour.action_conflict` record — losing proposals are typed, not last-write-wins.

**Actions.** Every action emits an `aas.behaviour.action_started` record (instance, digest, revision, transition, action ID, kind) that enters the causal graph before the effect. `set` writes only owned fields through the transition; `emit` publishes a registered schema on its declared topic; `command` submits a `CommandRequest` with a kernel command ID, rejects re-use of a non-terminal child ID, and requires bound role generations to still be alive; `cancel_command` requires a submitted receipt and a message descriptor advertising `cancel_support` — a physical owner that cannot cancel is never fabricated a cancellation; `delay` schedules a positive duration, with `duration_ns: 0` compiling to a timer at the next microstep of the same ns (an explicit `ScheduleTimer`, not a hidden recursion); `cancel_timer`, `assert_relation` (half-open validity, canonical stamp), `close_relation` (a particular edge ID), `create_entity` (identity + next generation, lifecycle authority pre-checked), `remove_entity` (only after real child cleanup receipts), and `complete` (optional explicit status).

**Deadlines and budgets.** A chain `deadline_ns` arms an instance deadline at activation; a command `deadline_ns` arms a child deadline (revision of the acting state); `cancel_command.timeout_ns` arms a cleanup deadline. Deadlines fire as typed `deadline` triggers that transitions may consume — they mark overdue work and never synthesize a physical failure or cancel receipt. The timer budget counts delays plus outstanding deadlines. Kernel `max_microsteps` (default 1024) bounds cascades; per package, `max_transitions_per_instance_per_ns` (compatibility default 64), `max_instances`, and the timer/creation budgets fault with instance/transition/cause context instead of silently dropping work.

**Completion.** On entering a terminal state (or an explicit `complete`), the chain's `completion_policy {children, statuses, policy}` is checked against the actual child statuses accumulated from real receipts; unsatisfied requirements raise `RuntimeError` rather than completing on transport acknowledgement. Otherwise the instance status becomes `failed` for terminal states `failed`/`rejected` and `completed` otherwise, the deadline is canceled, and the record is closed.

## 6. Conflict rules, records and causes

A conflict rule binds roles, references a predicate and edge, and is evaluated with the identical `Evaluator` contract in binding order. On a fresh matching edge the executor records `aas.behaviour.conflict` (rule ID, package digest, predicate, evaluation record, roles) on the records topic, cites the evaluation as cause, and emits the rule's typed event — with an authored payload, or one derived from the event schema's members (role refs, plus `actor` for single-role rules). Chains subscribe to that event through ordinary event triggers.

All orchestration state is journaled, never private console state: lifecycle records (`created`/`transitioned`/`completed`/`failed`/`canceled`) as bitemporal assert/close pairs carrying template, binding, package digest, roles, state, revision, variables, children (command ID, status, receipt reference), transition ID and trigger; `predicate_evaluated` truth records from both profiles; `action_started`; `conflict`; `action_conflict`. Every triggered step can cite its initiating delivery, timer payload, evaluation record and consumed fact/relation versions through the kernel's cause lists.

## 7. Injection gateway

In-package `injection_points` declare `{id, stream_id, command, target, emits, topic?}`; `target` must be the behaviour engine itself and `command` either `aas.runtime.inject_event` or a dedicated registered command schema. The gateway (`_inject`) accepts command deliveries whose payload has `injection_point` + `payload`; an unknown or ambiguous point is rejected, the payload is validated against the point's `emits` event schema, and the event is emitted preserving the delivery's original `at` and `source_stamp`. `accept`/`execute`/`succeed` receipts are separate from downstream execution.

The service path is `POST /v1/runs/{id}/ingress` with `{schema, target, at_ns, payload, source_stamp{clock_id, numerator, denominator, mapping_id}, stream_id, idempotency_key?}` (`services/app.py`, `platform/ingress.py`). Before K4 admission, `services/worker.validate_injection` checks the pinned manifest without mutation: the point exists exactly once for that command, engine/target match, `stream_id` equals the point's declared stream and that stream is bound to the engine, and the payload validates. The receipt is `aeroagentsim.ingress-receipt/v2` (`stream_id`, `disposition accepted|delayed|rejected`, `journal_index`, `mapped_ns`, `command_id`, boundary/activation/delay fields, `code`) — **admission only**. An idempotency key re-submission returns the same receipt. `POST /v1/runs/{id}/watermark` / `advance_watermark(ns, stream_id=...)` close named-stream prefixes; offline scheduled commands use ordinary `bindings.commands` entries and no pretend live watermark. `scenarios/behaviours/minimal.yaml` shows the complete wiring (`ingress_streams` with `initial_watermark_ns`, `lateness: reject`, `timeout_s`, plus a scheduled injection).

## 8. Sampled wiring: explicit Q6 engines, `bindings.samples`, and the return lag

There is no behaviour-side sampled-context construction. A sampled predicate consumes an explicitly configured Q6 `predicate` engine:

- The scenario declares a `predicate` engine with its `target` definition, `context`, `event`/`topic`, `parameters` and (for relation nodes) `relation_profiles` with pinned source/clock; the Q6 engine requires exactly one matching `bindings.samples` entry (`context`, `partition` equal to that engine, `upstream`, `bindings`, `sources`, `clocks`, `parameters`) and rejects parameter mismatches. Native dialects other than the four supported `nativeDialect` values fail at load.
- When a behaviour engine is present, `platform/simulation.py` swaps that engine for `RecordedPredicate`, which adds `aas.behaviour.predicate_evaluated` to the partition's emits and the `aas.behaviour.sampled` topic to its targets. After the normal Q6 sampled pass, every `SampleFrame` result is re-emitted as a portable truth record (roles, status, value, diagnostics, `readCut`, per-role/per-field `acquired` with clock, mapping and producer, validity pair).
- The behaviour partition subscribes to `aas.behaviour.sampled`; `_truth` matches records by the predicate's `adapter.context` and requires exact role agreement, otherwise returning `required_input` with the recorded diagnostics.

**Feedback lag is the declared dependency graph, not a hidden delay.** A sampled predicate must match its actual Q6 context, role aliases, resolved expression, event and parameters at scenario load. The return path from behaviour-owned writes back into a sampled predicate's upstream cone exists only as kernel routes: the behaviour partition's `message_lag_ns` (engine config, default 0) and any lagged field/relation dependencies. The kernel rejects a zero-lag sampled feedback path (`SAMPLE_CYCLE` in `aerokernel/sampling.py`) and non-reactive reaction cycles (`CYCLE_REENTRY`); a sampled-feedback consumer must declare a positive route/dependency lag, and the kernel's validation is retained verbatim — no 1 ns is added implicitly. There is no behaviour-side "feedback" profile or lagged-partition compiler stage in this implementation.

## 9. Determinism and replay

Ordering inputs are fully pinned: instance identities are content digests (run, epoch, package digest, binding, chain, sorted roles, episode); binding iteration is package order then binding ID; tuple enumeration is role-name order over sorted live refs; candidate execution is `(-priority, bindingId, instanceId, authored index)`; conflict rules run in package/rule/tuple order; arbitration and `writes` reservation follow that same order. No wall-clock, thread or model completion ordering enters. A hypothesis-driven test in `tests/behaviours/test_runtime.py` permutes independent binding declarations and asserts an identical recorded `aas.behaviour.*` trace.

`RunSession` freezes the resolved packages at run creation: `behaviour.ir.json` (packages + evaluator version) and a `manifest.json` extension with `epoch` and `behaviour_digests` (`{package, ir}` digests). Replay is kernel journal replay: instances, states, evaluations and receipts are reconstructed from records, with **zero** evaluator, engine or model calls — the runtime test monkeypatches `Evaluator.run` to raise and asserts the projected records and final state are identical. An incomplete or faulted journal stays incomplete/faulted.

## 10. Legacy compatibility executors

`behaviours/compat.py` contains the actual former `engines/workflow.py` and `engines/threshold.py` interpreters, moved unchanged: `LegacyWorkflowExecutor` (authored-order DES machines, OR trigger categories with an optional AND guard, consumed unmatched events, state-entry timers, children surviving state changes, `max_entry_transitions` bound) and `LegacyThresholdExecutor` (one sampled comparison/presence operator over a pinned `bindings.samples` context, `native_reference` source pin, `entered` emission from prior frames). Their comparators, timer payloads, receipts and error messages are the historical ones; the alias modules re-export `build_legacy_workflow` / `build_legacy_threshold`. Reexecution of `scenarios/p1-slice.yaml` against the historical HEAD classes and these compatibility classes produced 1,624 identical canonical journal records (14,706,768 bytes; SHA-256 `715d9f6e9964e1148e54c70ebf84a207cdd7440e06949176f844f88cda6a32db`). The raw WAL bytes also matched (8,885,797 bytes; SHA-256 `3bf93d250900b81267e7f1dd4123875bbf64d11a6a2220f84e25ed65805602ec`). This measured case does not claim universal byte equality; kernel replay of any recorded prefix calls no interpreter.

`compile_workflow` / `compile_threshold` produce **descriptive** IR only (`legacy_workflow/v1`, `legacy_threshold/v1`: machines, trigger kinds, verbatim comparator strings, selector/path/parameter echo), written to `behaviour.compat.ir.json` by `RunSession` for legacy engines. They do not convert legacy configs into behaviour packages, into the Q6 evaluator, or into any generic IR — interpretation stays exclusively with the legacy executors. `workflow` and `threshold` are selected from the same behaviour factory module and share the kernel DES coordinator. Their legacy interpretation remains selectable to preserve recorded semantics; it is not a conversion into the new chain IR.

## 11. Exact deltas against the RUNTIME target

Read `RUNTIME.md` §2–§5 for the design; the implementation differs exactly here:

1. **Sampled contexts.** No `sampled_contexts`/feedback construction by the behaviour compiler. Sampled predicates reference explicit Q6 `predicate` engines and their pinned `bindings.samples` entries via `adapter {event, context}` (§8); the predeclared finite context domain is the Q6 sample binding, unchanged.
2. **Return lag.** The sampled-feedback return path is the actual partition dependency/message-lag graph (`message_lag_ns`, lagged dependencies) validated by the kernel, not a compiler-placed lagged partition and not a delay inside an action (§8).
3. **Selectors.** `stable_id`, `choose`, `selector` and award-style selection keys are rejected at compile; awards/choices belong to an explicit domain computation owner communicating through typed commands/events (§2).
4. **Completion schema.** `{children, statuses, policy}` exactly, checked against real child receipts at terminal entry (§2, §5).
5. **Reactive evaluation is stateless.** The committed-reactive profile forbids native temporal/window operators and time leaves; only the sampled profile reaches Q6's native temporal semantics, through the single `RecordedPredicate` adapter (§4).

## 12. Recorded feed projection (handoff to job E)

`services/projector.py` projects only committed `Emit` proposals for `aas.behaviour.predicate_evaluated` and the five lifecycle schemas. Enqueue and dispatch records never create another extension version. The existing feed contract and commit indices remain unchanged. A commit with truth records has `predicateTruth`; one with lifecycle records has `chainInstances`. These optional arrays are absent when the commit carries no corresponding records, preserving the exact legacy commit shape.

Each entry preserves the emitted record's keys, including `op`, original `validFrom`, current `validTo`, diagnostics, trigger and child receipt references. Chain entries additionally retain the actual `status` and `requiredInputs` diagnostics during producer warmup. It adds `available` from the emission commit's `Instant`, `version: {journalIndex, itemOrdinal}` from that proposal's WAL location, and its recorded `causes` list. `roles` maps each role to the existing viewer `EntityKey {id, generation}`; its namespace is the header's `runId` and actual manifest `epoch`. Large generations are decimal strings, and other large portable integers use the existing lossless `$integer` convention. Unknown/invalid records retain null values and diagnostics.

The optional header `behaviour` contains `extensions: [predicate-truth/v1, chain-instance/v1]`, evaluator metadata and `packages` entries `{id, packageDigest, irDigest, evaluator, predicates, chains, bindings}` from `behaviour.ir.json`. It never recompiles a predicate or opens today's native source during projection. Older runs without that artifact have no behaviour header. Both paged replay and SSE already call this projector.

## 13. Changes required in job B's current accident package

The read-only package at `wt-b/scenarios/demos/traffic-accident/behaviours.yaml` exists and was submitted to this compiler. It currently fails at `$` on `feedback`, `requires_compiler_features` and `sampled_contexts`. No accident engine run or kinematic/stub-decision smoke is claimed. Removing those declarations alone would still leave these semantic differences:

| Current B construct | Required authored change |
| --- | --- |
| Top-level `sampled_contexts` | Declare real Q6 `predicate` plugins and finite `bindings.samples` in the scenario. Put `adapter: {event, context}` on each sampled package predicate. Copy Q6's **resolved** AST and exact bound parameters, not unresolved native rule references. |
| `feedback` | Declare the actual positive dependency/message return lag in the scenario's engine graph. A single behaviour partition currently has one `message_lag_ns`; it does not split selected feedback paths automatically. Do not remove lag without rechecking the modeled latency and kernel cycle admission. |
| `requires_compiler_features` | Move requirement notes into documentation; unsupported execution features must first be compiled explicitly, rather than disappearing when this list is removed. |
| `evaluator.source_sha256` | The runtime pins Q6 Python evaluator source hashes in IR and Q6 native references in each sampled plugin. This extra field is not accepted. Keep the actual native provenance in the pinned snapshot/plugin definitions and `native_references_ref`. |
| `retry_policy` | Express rejection, bounded attempt state, delay, revalidation and retry as explicit transitions and owned fields. Use actual rejected receipts and their typed reasons; no invented successful retry. |
| Binding `selection: minimum_known_feasible_eta` | Supply an explicit typed decision/computation producer for the finite candidate join, missing-input handling, stable tie break and selected ref. A chain guard must revalidate the current eligibility predicate before issuing award/assignment actions. The generic executor does not implement this selection policy. |
| `stable_id` / `stable_entity_ref` | Supply authored literal IDs for finite entities, or typed IDs/refs from the declared producer. Automatic **chain instance** IDs are already deterministic; this does not create arbitrary business entity IDs from events. |
| `relation_assertion_id` | Read/carry the actual edge ID from a typed event/producer result or declare the finite authored edge ID. Closing requires a particular committed active assertion, not just a relation name. |
| `typed_choice` | Use separately guarded transitions or a typed decision result. A literal mapping is not executed as a choice. |
| Binding variables reading `$trigger` | Bind variables to committed fields, roles or literals. Use `$trigger.payload.…` and `$trigger.result.…` directly in transition actions after the real event/receipt exists. Cross-variable binding computations are not supported. |
| `correlation.requires_event` | Store the prerequisite in explicit chain state or a committed fact and guard it. Ordinary correlation compares members of the current event payload; it is not durable event history. |
| Receipt `result_matches` | Supported: a mapping from actual result member names to typed expected expressions. It never matches an absent member. |
| `completion_policy.requires`, `failure_terminal`, `deadline_action` | Use `{children: [actual child IDs], statuses: [succeeded], policy: all}` plus explicit terminal/deadline transitions. Stored-image/edge-acceptance events need explicit states and predicates over their real correlated records; a transport receipt alone is insufficient. |
| State-spanning upload deadline | Use chain `deadline_ns` with `on: {deadline: instance}`, or an actual command child deadline. State-entry delay timers are canceled on transition. |
| Injection command | Prefer `aas.runtime.inject_event`, the declared point's stream/target, and exactly `{injection_point: <id>, payload: <typed event payload>}`. Dedicated commands must have this same wrapper and actual registered result schema. |

These repairs must preserve B's detection, medical-task interruption, eligible award, physical arrival/dwell, capture storage and edge acceptance semantics. They cannot be validated by deleting unsupported instructions or substituting fixture metadata for actual capture evidence.
