# AeroAgentSim 产品逻辑（判定实现是否正确的依据）

> 本文是产品逻辑的唯一依据。实现、页面、接口与此冲突时，以本文为准。
> 开发计划、差距分析和接口契约见 [plan.md](plan.md)。

## 1. 产品中心：一个世界，一个操作台

AeroAgentSim 的主界面应当是可交互的 3D 数字孪生工作台。

用户进入项目后，看到场景、具体对象及其状态，在同一个工作区完成观察、操作、检查和回放。配置文件与表单负责定义这个世界；算法和仿真引擎负责驱动它；AeroGraph 提供契约。

必须区分四个东西：

| 概念 | 例子 | 职责 |
|---|---|---|
| 类型契约 | 无人机类型、位置字段、电量字段 | 定义对象有什么字段、关系和能力 |
| 实体实例 | 无人机-007 | 世界中有身份、有状态的具体对象 |
| 视觉素材 | 某款无人机 GLB 模型 | 表现对象外观、尺寸、朝向 |
| 执行组件 | 运动引擎、通信引擎、任务分配算法 | 计算状态或产生动作请求 |

添加无人机，是创建一个符合契约的无人机实例，绑定模型、初始状态和执行组件。不能把浏览契约类型等同于放置实体。

## 2. 主界面的布局与交互

| 区域 | 显示内容 | 交互结果 |
|---|---|---|
| 顶部 | 项目、场景版本、运行状态、仿真时间、运行控制 | 启动、暂停、恢复、停止当前运行 |
| 中央主区域 | 城市、地面、建筑、车辆、无人机、人员及空间覆盖层 | 旋转、缩放、选中、聚焦、跟随、查看轨迹 |
| 左侧对象列表 | 当前世界的具体对象、分组、搜索和筛选 | 定位对象，同步选中 3D 与关系图 |
| 右侧检查器 | 选中对象的状态、任务、行为、可执行操作及回执 | 检查对象，提交被允许的操作 |
| 底部 | 时间轴、事件、命令、执行结果 | 定位发生时间、涉及对象和因果链 |
| 辅助视图 | 对象关系图、表格、统计 | 从非空间角度观察同一个世界 |

交互边界：

- 移动相机、选中对象、切换图层只改变观察方式。
- 编辑位置、数量、设备能力等配置写入场景草稿。
- 运行中调度无人机、改变任务、注入事件提交真实命令，由负责的组件执行，界面等待回执与状态更新。
- 不能拖动一个模型，就直接把仿真中的真实位置改掉。
- 没有空间位置的任务、订单、通信关系等，通过关系图、列表和检查器操作，不能伪造坐标塞进 3D。

## 3. 配置：文件和表单编辑同一个场景

| 配置部分 | 内容 |
|---|---|
| 场景与空间 | 地理范围、坐标系、地形、城市素材、道路、空域 |
| 对象 | 具体类型、数量、实例身份、初始位置、属性、模型绑定 |
| 关系与资源 | 隶属、连接、服务关系、设施容量、资源归属 |
| 任务与行为 | 任务定义、触发条件、前置条件、动作、事件链 |
| 执行组件 | 运动、交通、通信、能耗、天气等引擎及字段归属 |
| 算法与智能体 | 算法选择、参数、作用范围、模型与工具权限 |
| 运行与记录 | 时长、步进策略、随机种子、输入源、输出与录制 |

正确的配置流程：

打开场景 → 修改草稿 → 校验 → 保存版本 → 初始化场景 → 明确启动运行。

- 文件和表单是同一份配置的两种编辑方式。
- 3D 显示配置对应的场景；选取空间位置可以辅助填写坐标表单。
- 保存、校验、载入场景，都不应擅自启动仿真。
- 校验失败，应定位到具体对象、字段或绑定。
- 正在运行的场景使用固定版本。修改配置形成新草稿，不静默改变正在运行的世界。
- 模板提供可复用的场景配置，不能用模板演示状态冒充运行结果。

## 4. 算法、行为规则、引擎必须分清

| 层次 | 回答的问题 | 示例 |
|---|---|---|
| 算法 | 如何选择方案？ | 任务分配、路径规划、冲突消解、充电决策 |
| 行为与规则 | 什么条件下允许做什么？ | 低电量返航、医疗任务不可中断、事故触发响应 |
| 领域引擎 | 动作如何执行，状态如何变化？ | 飞行动力学、道路交通、通信、能耗 |
| aerokernel | 何时生效、谁能写、记录什么？ | 统一时间、字段所有权、命令与事件、事务、日志 |

算法配置必须绑定到具体任务、对象群或执行组件，明确输入、输出、参数和适用范围。

LLM、LangGraph、学习策略属于可选决策实现。其输出进入同一条执行链：

观察状态 → 提出决策 → 检查条件和权限 → 提交动作 → 负责组件执行 → 返回回执 → 提交状态变化。

算法选择、参数修改与运行结果检查是不同操作。运行中能否更换算法，必须由实际能力决定，不能让一个下拉框造成隐含热切换。

## 5. AeroGraph：契约与开发支撑层

沿用已有七个一级分类及其二级分类：物理实体、网络与计算、电磁、环境与空间、法规与运行约束、业务与运行、信息与记录。

它负责支撑：类型定义与实际继承关系；字段类型、单位、坐标系及约束；关系端点与约束；谓词、事件和命令的定义；配置校验、表单生成及组件接口检查。

分类目录用于组织内容；字段继承依据真实的类型继承关系。不能因为两个类型位于同一目录，就认为它们具有相同字段或执行能力。

| 图 | 节点是什么 | 用途 |
|---|---|---|
| AeroGraph 契约图 | 类型、字段、关系定义、谓词与事件定义 | 开发、扩展、检查契约 |
| 运行关系图 | 当前世界中的实体、任务、资源、事件及其联系 | 运行观察、检查和操作 |

普通用户配置“无人机”“车辆”“餐厅”，底层使用 AeroGraph 契约。需要扩展类型或检查字段来源时，再进入契约工具。

## 6. 主要界面跳转逻辑

| 从哪里操作 | 去哪里 | 必须保留或明确的上下文 |
|---|---|---|
| 项目入口：打开项目 | 数字孪生主工作台 | 项目、所选场景和版本 |
| 项目入口：从模板创建 | 场景配置 | 新建独立草稿，保留模板来源 |
| 主工作台：配置场景 | 配置面板或配置工作区 | 当前项目、草稿版本；运行仍独立存在 |
| 配置：选择算法 | 算法配置区域 | 算法作用对象、任务或组件 |
| 配置：检查字段定义 | AeroGraph 契约详情 | 当前字段和类型；返回原编辑位置 |
| 配置：校验失败 | 对应配置项 | 错误位置、原因及未保存内容 |
| 配置：校验完成并启动 | 主工作台的实时运行状态 | 新运行身份及固定配置版本 |
| 3D：选中对象 | 右侧对象检查器 | 同步列表、关系图中的同一对象 |
| 关系图：选中实例 | 同一个对象检查器 | 有空间位置时可聚焦 3D |
| 检查器：查看任务或事件 | 任务详情、事件链或时间轴位置 | 保留关联对象与所选时间 |
| 检查器：执行操作 | 操作确认与回执区域 | 显示提交、接收、执行、完成或失败 |
| 主工作台：查看记录 | 运行记录列表 | 当前运行仍可返回 |
| 运行记录：打开某次运行 | 主工作台的回放状态 | 加载该次运行的配置、素材和日志 |
| 运行记录：选择多次运行 | 对比工作区 | 明确配置差异、指标和时间对齐方式 |
| 回放：查看当时决策 | 决策详情 | 保留运行、对象、事件和时间位置 |
| 运行：修改后再试 | 从该运行配置建立新草稿 | 保留原运行，记录派生来源 |
| 任意工作区：帮助 | 上下文帮助 | 返回时恢复原工作位置 |

切换 3D、关系图、表格、检查器属于同一工作台内的视图切换，不应反复跳到互相失去上下文的独立页面。

## 7. 时间、状态和返回逻辑

- 仿真控制与回放控制分开。暂停回放只停止浏览历史；暂停仿真才停止运行推进。
- 实时运行中查看历史时，明确显示“正在查看历史时刻”，并提供“返回实时”。
- 3D、关系图、检查器、事件列表使用同一对象身份和同一查看时刻。
- 点击历史事件时，定位到事件对应的记录位置，不能同时显示对象未来才发生的状态。
- 切页面、返回、刷新不能隐式启动、停止运行或重复提交命令。
- 未保存的配置必须保留或明确处理，不能因跳转丢失。
- 刷新与重连依据后台真实运行恢复；失败、缺失和等待都要如实呈现。
- 回放读取已有记录，不重新调用模型或重新执行仿真。
- 相机运动和视觉插值只改善显示，不改动权威状态与事件时间。

## 验收主线

打开外卖场景 → 用表单配置餐厅、无人机、订单与算法 → 校验并保存 → 在 3D 中查看初始世界 → 启动 → 选中配送无人机查看任务 → 注入餐厅延迟 → 查看调度变化与执行回执 → 在时间轴回看原因 → 从该次配置建立对照场景并比较结果。
