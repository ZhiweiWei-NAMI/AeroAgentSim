# 从空白项目到真实区域上的仿真运行

[English](blank-project-tutorial.md) · [指南索引](README.md) · [安装与验收](../../INSTALL.md)

本教程走手动工作台流程：**场景入口（Gallery）→ 配置（Configure）→ 空间 → 对象 → 关系 → 任务 → 执行组件 → 算法 → 验证 → 保存版本 → 初始化 → 启动 → 因果检查／回放**。不需要连接 LLM。先用一个已配置的小范围 OSM 地图源，安排短时运行，检查第一条事件链。

下文按钮采用本次区域／对象配置接口约定的名称。如果旧版前端没有按钮，或服务返回 404／422，保留草稿、阅读错误并核对前后端版本与可用能力。缺少操作或预览字段不等于该步骤成功；本文不代表某个未测试部署已通过验收。

## 1. 从空白项目开始，先分清概念

在 **Gallery** 点击 **跳过，手动创建（Skip, create manually）**，再打开 **配置（Configure）**。新草稿没有已编写的机队或工作量。可返回任意配置部分；保存草稿、冻结版本与开始执行是不同操作。

| 概念 | 你正在配置什么 |
| --- | --- |
| 类型契约 | 项目 AeroGraph 快照／目录中的字段、单位、关系与能力；抽象类型不能实例化。[契约](../concepts/aerograph.md) |
| 实例 | 具有稳定 id 的一个对象，例如 `courier-1`；选择类型不等于创建实例。 |
| 视觉模型 | 展示外观、尺寸与朝向的 GLB 网格或程序生成标记；不计算电量、飞行或配送状态。[资产](../../ASSETS.md) |
| 物理／执行模型 | 拥有字段并执行命令的运动、能耗、天气、交通或任务引擎；通用运动学引擎不是完整配送模型。[组件](../concepts/plugins.md) |
| 算法 | 选择分配或路径等方案的方法；算法插槽必须由实际引擎读取。[算法](algorithms.md) |
| LLM | 提出权限范围内动作的可选决策实现；手动配置、确定性规则与回放不需要模型。[智能体](agents.md) |

模板是示例：它预先提供快照、黄浦坐标、对象或机队生成器、业务引擎、算法与规则，复用时仍要检查其假设。任意 OSM 区域只提供源几何，不会自动补齐无人机、充电容量、订单、碰撞处理或完整仿真。

## 2. 空间 → Region：预览、审阅、应用

打开 **配置 → 空间（Space）→ 区域（Region）**。使用新的 OSM 区域时，把固定 `city: huangpu` 选择清为 `none`，避免示例城市与编译区域竞争。

1. 从已配置目录选择地图源。`GET /v1/studio/catalog` 的 `extracts` 给出标识和已知边界；它不是地名搜索，也不是任意服务器文件上传。没有配置覆盖时，自带源为 `wujiaochang`；黄浦展示资源包属于另一份来源。
2. 按 `[west, south, east, north]` 填写 **边界（bounds）**，单位为 WGS84 度，范围应位于源数据覆盖区。东必须大于西，北必须大于南，不能把 ENU 米制坐标填进去。
3. 明确填写米制原点海拔 `alt` 与层高 `level_height_m`。例如 `0` 和 `3` 是建模假设，不是测量地形或建筑高度。原点根据所选边界计算。
4. 点击 **预览区域（Preview region）**，审阅边界、新旧 ENU 原点、原点位移、建筑／道路数、署名、高度来源与全部诊断。预览不写入数据。缺失值仍是未知；成功且建筑数为零不同于请求失败。
5. 检查受影响的有位置实体、`network_invalidated` 与 `city_conflict`。原点变化不会自动平移已有坐标，同一组 ENU 数字可能对应不同地理地点。若不符合预期，取消或先调整位置。
6. 审阅后点击 **应用区域（Apply region）**。界面先保存本地编辑，再执行服务操作并采用返回的工作区。应用保存区域及编译结果，使旧道路网络失效，不会启动运行。返回空间部分可检查已保存区域。
7. 如需道路交通，可在应用后点击 **生成道路网络（Generate road network）**。后台使用 SUMO `netconvert`，服务器必须真实安装它。生成失败不是可用网络；替换区域后必须重新生成。[SUMO](sumo.md)

高度标签与外观应分开：OSM `height` 是源数据报告的高度；`building:levels × level_height_m` 是明确估计；两者都没有时，建筑保留轮廓，高度缺失。ENU 地面是声明范围内的平面坐标面，不是测绘地形。看起来像屋顶的网格或城市选择都不能证明着陆点有效；位置要依据真实来源和已声明假设。

### 按钮背后的区域 API

[HTTP API 参考](../reference/http-api.md)与[地图工具](../../tools/build_map.py)是高级路径。工作区 `WORKSPACE_ID` 的预览接口：

```text
GET /v1/studio/catalog
POST /v1/studio/workspaces/WORKSPACE_ID/region
```

```json
{
  "extract": "wujiaochang",
  "bounds": [121.50, 31.29, 121.51, 31.30],
  "alt": 0,
  "level_height_m": 3,
  "dry_run": true
}
```

上述边界仅为说明格式的示例，不保证源覆盖；实际采用目录与研究区域的边界。响应为 `{"preview": {...}}`，包含 `extract`、`bounds`、`origin`、`previous_origin`、`origin_shift_m`、`buildings`、`roads`、`attribution`、`height_source`、`diagnostics`、`affected_entities`、`network_invalidated`、`city_conflict`；部分原点值可为 null。应用前先保存草稿，再发送同样的源／边界／假设并去掉 `dry_run`，响应为更新后的工作区。此区域契约不接受 revision 字段。404／422 或缺少预览表示能力不可用／输入无效，不能据此盲目应用。

已有道路网络接口为 `POST /v1/studio/workspaces/WORKSPACE_ID/network`；几何可通过 `GET /v1/studio/workspaces/WORKSPACE_ID/buildings.geojson` 检查。

### 添加新的地图源（由服务配置者操作）

区域 API 编译的是**服务配置的本地 OSM XML**，不是每次点击都在线下载。配置者可在已安装环境的仓库根目录，用 [tools/build_map.py](../../tools/build_map.py) 准备输入：

```sh
python tools/build_map.py --osm src/aeroagentsim/authoring/assets/wujiaochang.osm.xml --out generated/my-region --alt-m 0 --level-height-m 3 --public-url https://your-host.example/maps/my-region/city.geojson
```

这个可复制的离线示例编译仓库自带 XML。自己的区域应把 `--osm` 换为真实本地文件。也可把输入选项换为 `--fetch-bounds W S E N`（填写四个实际数字），并可用 `--endpoint URL` 指定来源。默认端点为 `https://api.openstreetmap.org/api/0.6/map`，请求带 `?bbox=west,south,east,north`。下载前选择小范围，检查端点、ODbL 条款与输出位置。工具不估算下载大小，也不进行交互确认。

输出包括 `source.osm.xml`、`city.geojson`、`scene.json`、`presentation.json`、`provenance.json` 与 `ATTRIBUTION.txt`。检查诊断、来源、边界及海拔／层高假设，保留源与来源记录。`--public-url` 是你填写的 URL；脚本不会托管它、注册地图源、制作 Release ZIP、生成资产摘要或 SUMO 网络。单独使用 presentation 时自行托管该 URL；工作区 API 会提供自身的编译几何。

启动服务前，将 `AEROAGENTSIM_OSM_EXTRACTS` 设为 JSON 标识到本地文件的映射，例如 `{"my-region":"/absolute/path/to/generated/my-region/source.osm.xml"}`。此设置替换自带列表，要保留的源都需列出。以此配置重启，确认 `/v1/studio/catalog` 出现 `my-region`，再在 Region 选择。API 从 XML 重新编译所选边界，不导入 `scene.json` 路径，也不把生成目录当作已安装黄浦包。

## 3. 对象 → Add objects

点击 **添加对象（Add objects）**，选择项目契约目录中可实例化的类型、id／前缀、数量、放置类别与执行组件。小型教学配置可包含两架 UAV、取货设施和目的地设施；这些是你编写的实验输入，不是从 OSM 建筑自动推断的对象。

位置填写相对于区域原点的 **ENU `[E, N, U]` 米制坐标**：东、北、上。三维渲染中东映射到 X、北映射到负 Z、上映射到 Y；表单仍填 ENU，不填渲染坐标。选择真实源位置，或明确把手填位置标为假设。数量大于一时必须生成不同实例 id；逐一检查位置，不能假定它们自动占据不同屋顶。

检查初始事实、单位与字段所有者。通用放置支持 `entity`／`facility`／`airspace` 和 `kinematic`／`workflow`。运动学放置会写入初始速度与能量假设，它们是可编辑输入，不是测量值。其他插件需明确的引擎配置与绑定；通用 UAV 放置不会自动附加低空配送任务模型。缺少具体类型或执行者时，先完成真实配置，再声称配送实验可运行。

实例表格与草稿预览应一致。生成器机队数量与显式实例数分开，运行时展开可在初始化后查看。逐行 **移除（Remove）** 前检查依赖；取消保留对象，确认移除应同时清理引用，不能留下损坏任务。

## 4. 关系 → Add relation

点击 **添加关系（Add relation）**，选择当前契约中的关系和真实源／目标实例，核对端点类型与方向。设施容量、开放状态、充电资源和服务归属另行检查；起名“充电设施”不会创建充电功率或能耗执行者。无空间位置的订单与归属关系放在列表／关系图中，不伪造地图坐标。

关系或端点不可用时，先修复契约或对象；返回这些部分不会开始执行。[关系与契约](../concepts/aerograph.md)

## 5. 任务 → Add order stream，再配置规则

点击 **添加订单流（Add order stream）**，配置已接通的业务模型：任务类型、取货／目的地 id、数量／释放时间、载荷、优先级和适用的交付窗口。小型配送实验可选短时运行中的固定两单工作量；这些数量和时刻是实验输入。目标数、已释放数和完成数要分开。

空白运动／工作流世界尚不包含配送模板中的低空任务契约、生成器、站点事实、调度、能耗和命令绑定；编辑器应指出缺项。通过 **文件（File）** 导入完整兼容场景是高级路径，不代表缺失的手动配置控件已可用。[任务模型与生成器](algorithms.md) · [示例模板](templates.md)

打开任务规则编辑器，配置触发、参与者、带单位／阈值的类型化谓词、真／假或等待分支、动作与实际执行者。例如，天气／能量策略只有在引擎提供相应动作时才能让无人机等待或返航。核对每条保存的边和实体引用；图示或阈值本身不会调度命令。[谓词](predicates.md) · [事件链](behaviours.md) · [低空规则](lowalt-rules.md)

需要协同响应时点击 **添加协作（Add cooperation）**，填写观察者、事件时刻／位置、观察半径、交接点、协助者、受保护任务与电量限制。离线实验先明确选择 **预设（prescribed）** 响应者／协助者模式；智能体模式还需要运行期智能体引擎与真实提供方。无效回复或模型失败记录 `lowalt.incident.decision_failed`；响应者事件状态为 `decision_failed`。没有合格接受者时，若有协助者决策失败，交接为 `failed`，否则为 `declined`。之后预设模式按顺序选择后续允许选项；智能体模式根据当前状态重新请求决策。失败不是接受。[失败语义](agents.md#cooperation-failure-and-re-decision)

## 6. 执行组件 → Weather & traffic

打开 **天气与交通（Weather & traffic）**，填写风速；点击 **添加阵风（Add gust）**，填写秒制起止时间与 m/s 风速。阵风应位于运行时长内并记录为实验输入，例如 60 秒运行中的 10–20 秒阵风是配置计划，不是观测天气。天气引擎必须拥有并计算相关事实，飞行／任务模型也必须实际读取它们。

交通需将生成网络绑定到可用交通组件，再配置其支持的密度、时间与种子。生成道路本身不会产生行驶车辆。运动、能耗、通信与任务等其他引擎也需在执行组件中明确绑定：每个字段一个写入者，每个动作一个执行者。缺失插件或网络生成失败仍是错误。[天气](weather.md) · [SUMO](sumo.md) · [字段归属](../concepts/plugins.md)

## 7. 算法：检查实际使用者

根据实验选择分配、路由、冲突消解与充电插槽，检查参数与实际引擎使用者。描述符契约包含 `consumers: [{engine, plugin}]`；缺失／空列表表示适用性未知，不证明算法正在运行。引擎不读取该插槽时，下拉选择不能建立行为效果。修改影响下一个版本／运行，不会静默热切换实时运行。[算法](algorithms.md)

## 8. 验证 → 保存版本 → t=0 初始化 → 启动

在 **运行（Run）** 中明确时长与种子。首次检查可用例如 60 秒的短时 scheduled 运行。

1. **验证（Validate）**：定位各问题的部分／字段，修复真实契约引用、位置、字段归属与事件绑定。`/city` 冲突应通过选择固定示例城市或编译区域之一解决。区域预览成功不代表场景验证通过。
2. **保存版本（Save version）**：冻结已验证配置。后续编辑形成草稿，不改变此版本或当前运行。
3. **初始化（Initialize）**：在 **t=0** 检查真实实例、原点、城市／来源与初始事实。没有对象就是空世界，返回对象部分创建；几何载入失败时，地面平面不是所选区域。
4. **启动（Start）**：只有此操作推进仿真。观察运行状态与仿真时间，不把预览动画当执行。暂停／恢复／停止使用运行控件，查看早前记录使用回放控件。

## 9. 检查因果与回放

在列表或三维中选择实例，检查器与关系图指向同一身份。选择记录事件并打开 **为什么（Why?）**，检查触发、对应记录位置的谓词输入／结果、决策来源、提交命令、回执与提交后的直接后果。允许的提案不是已完成动作；未触发条件、拒绝动作、未知输入与决策失败含义不同。

打开 **运行记录（Records）** 回放，用时间轴同步检查各视图的同一历史位置。**返回实时（Back to live）**（`L`，不按 Shift）回到当前运行。回放读取日志，不重新执行物理、不请求新的模型回复、不创造成功事件。应用助手计划的运行可有 Story，按记录比较预期；空白项目不会凭空生成计划经过。

`results_final` 为 false 时，终态不代表 KPI／Story 已聚合完成，要等待最终记录；字段缺失时最终性未知。在同一最终记录位置比较目标／已释放／完成数，缺失指标不是零。调整实验时用 **修改后再试（Modify & retry）** 派生新草稿，修改一个假设，再重复验证／版本／初始化／启动；保留原运行作为对照。[可视化](visualization.md) · [运行与来源](../concepts/runs.md)
